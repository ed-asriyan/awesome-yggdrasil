# Contribution Guidelines

Thank you for helping to keep this list useful. This is a curation, not a collection: only add projects that you or another contributor can personally recommend.

## Adding a project

1. Check that the project is not already listed in [README.md](README.md) or [archive.md](archive.md).
2. Add it at the bottom of the most fitting category. If no category fits, open an issue to discuss a new one.
3. Use this format, with a short objective description that starts with an uppercase letter and ends with a period:

   ```markdown
   - [Project Name](https://example.com/project) - Short description of what the project does.
   ```

4. One project per pull request, with a title like `Add Project Name`.

## Inclusion criteria

- The project is built for, on top of, or directly extends the Yggdrasil network.
- The source code is public and the project has a license.
- It has documentation that explains what it does and how to use it.
- It has had activity within the last 12 months. Projects without recent activity, archived repositories and deprecated projects go to [archive.md](archive.md).

## Description rules

- Describe the project, not the list. Do not repeat the project name.
- Be objective: no taglines, marketing language or superlatives.
- Keep it to one sentence where possible.
- Use consistent naming and capitalization (for example `Yggdrasil`, `Android`, `iOS`).

## Updating or removing a project

If a project moved, was renamed, or became unmaintained, open a pull request or use the issue templates.

## Pull request checklist

- [ ] The entry follows the format above.
- [ ] The entry is at the bottom of the right category.
- [ ] The link works.
- [ ] The description is objective and ends with a period.
- [ ] The project meets the inclusion criteria.
